# 統計の追加案（未実装）

グラフを増やす前に「自分について、次に何を知りたいか」を起点にする。カレンダーはその日の事実、統計は繰り返す傾向と発見を担う。

## 優先したい組合せ

1. **タグの前後の変化**：タグを記録した時点にそろえ、直前・1時間後・3時間後・6時間後・翌日の経過を比較する。立ち上がり、持続、反動を探す。観測がない時間は空白にし、同じ時間帯・開始時の体調が近い日を比較相手にする。頻繁な同タグの投稿が重なる場合は一つの出来事にまとめる基準が必要。
2. **条件による違い**：全体平均では埋もれる「つらい日に限る」「夜に限る」「別のタグと同時のとき」を探す。初期は二条件まで。条件を細かくしすぎて数件だけの結論を作らない。
3. **発見の受信箱**：統計の入口には、再確認できた発見を最大2件だけ表示する。差の大きさ、比較した日数、別期間でも続いたか、元の記録への入口を付ける。保存・保留・非表示で整理できる。これは計算と表示の構想であり、現行アプリにAI分析機能があるわけではない。

## さらに比較したい候補

| 項目 | 知りたいこと | 計算上の条件 |
| --- | --- | --- |
| 回復までの時間 | 低調になってから、普段の状態に戻るまでどれくらいか | 観測の隙間に回復した時刻は特定できない。区間と、追跡が終わった例を区別する |
| 安定度 | 同じ平均3でも、ずっと3なのか1と5を往復したのか | 変化幅と隣接観測の変化を分ける。記録数や間隔の偏りも表示 |
| 過ごしやすかった時間 | 自分で決めた体調以上で過ごせた時間が増えているか | 記録回数を時間に読み替えない。十分な観測がある期間だけ範囲で推定し、未観測時間も併記 |
| 量の曲がり角 | 数量・強度と体調の関係は直線か、頭打ちか | 同じタグ内で数値の意味・単位をそろえる。薬の増減の推奨はしない |
| 順序と連続 | A→BとB→A、単発と連日のときで違うか | 発生前の体調、間隔、重なる出来事を考慮。単純な因果と呼ばない |
| 傾向の変わり目 | 以前の自分と、最近の自分で何が変わったか | 記録習慣の変化と体調の変化を分ける。古い関係が再現しなくなったことも示す |
| 似た日の続き | 過去の似た状態のあと、自分はどうなったか | 候補は過去のみ。近い記録と実際の後日を示し、予測の確実性を誇張しない |

## 総当たりを使う場合の原則

- 発見用の古い期間と、確認用の新しい期間を分離する。未来のデータを過去の予測に混ぜない。
- 多数のタグ・時間差・条件を試すと偶然の差が増える。検定をする場合は多重比較を扱い、同じ候補を繰り返し探索した影響も管理する。
- 日々の記録は独立ではない。日・週のまとまりを保った再標本化などを検討し、投稿件数を独立標本数として水増ししない。
- 欠測と未選択を区別する。未選択の体調3は既存仕様だが、記録のない時間は3ではない。
- 体調が悪いから休憩・服薬した可能性がある。前後関係や調整を加えても、観察記録だけで因果を確定しない。
- ダミーデータは表示・計算・既知のパターンを検出できるかの試験に使う。実生活での予測性能の根拠にはしない。
- 次に必要な記録を一つだけ提案する案もあるが、頻繁な通知や入力項目の追加を前提にしない。
