# 検証記録 — 120日分の日内ログと日付操作

## 対象と実行境界

基準はSitesのf3e3144c7e0a78ac8f005093d0f5345e4d7e5861、GitHub mainの1dfc26d8e93f65f7ba6f9810d58db2ef59c88a31（同じツリー）。既存の依存と管理プレビューを再利用。必要境界はsource、runtime、依存、型検査、実SQLite、プレビューのD1/API、実ブラウザー、製品ビルド、正式な配備。Docker・新規外部サービスは不要。

## 原因と修正

- 試用モードはページ全体を再読み込みし、URLとReact状態が別のタイミングで切り替わっていた。利用領域を固定したリクエストをContextで渡し、集計・タグ・最初のページを用意してから一括切り替え。
- 日付入力はブラウザー操作で変更が反映されないケースを再現。input/changeの両方を受ける。異なる検索条件の取得を中止し、世代番号で古い応答の反映を防止。
- 画面復帰のたびに履歴を40件へ戻す処理を撤去。同じ条件の保存後更新では取得済みの件数を維持。非表示タブでは自動追加読み込みを止める。
- 日ごとの高さを小さく仮定するcontent-visibility指定を撤去。日内件数の多いグループのスクロールを安定させる。
- 手帳固有の日付状態を撤去し、入力欄の上の7日列を削除。日付選択は入力欄の下にまとめ、カレンダーから履歴・時間軸への移動で共有。
- 固定5件/日を120日・2〜56件/日・計2,510件へ変更。初期化はJSON入力2クエリの同一バッチ。新しい試用領域は`:demo:v2`で、通常の記録および以前の試用領域を上書きしない。

## 自動検証

24件のテスト成功。実SQLiteで全2,510件のページング、全日集計の一致、40件超の日・月境界の日付絞り込み、未入力日の空配列、利用者分離、再投入の冪等性を確認。型検査成功。Lintエラーなし（既存のテスト未使用変数警告1件）。

## ブラウザー検証

管理プレビューのD1/APIを使い、デスクトップと390×844の同一オリジンiframeで自然なクリック・日付入力・スクロールと画像の目視確認を実施。

- 試用データ初回投入、通常記録との往復、既存の通常記録を保持。
- 9月16日は40件から56件へ読み込み、全件が同じ日付、ID重複なし。
- 全期間スクロールで80件→120件へ自動追加し、9月19日→18日→17日→16日の境界を表示。別タブ操作後も120件を保持。
- Apple風・手帳配置で8月1日へ絞り込み。入力欄の上の日付一覧がなく、下の絞り込みで総括と履歴が連動。
- カレンダーから9月16日の56件へ移動し、時間軸に変更しても9月16日・56件を維持。
- 時間軸で通常モードの今日0件→試用モードの最新日48件へ切り替え。試用モードの初期日が空の今日にならない。
- アプリ由来のコンソールエラーなし。ブラウザー拡張機能側のメタデータ送信エラーは別。

検証専用ページは公開前に撤去。実機Safari/Androidでの試験と、本番個人記録への操作は行っていない。本番URLは管理ブラウザーの対象外で、公開成功は正式な配備結果で確認する。
